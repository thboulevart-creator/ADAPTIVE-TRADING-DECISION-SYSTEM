# 3. Règle d'interprétation de la matrice

Pour éviter toute circularité, chaque ligne doit être lue dans cet ordre :

1. **B2 établi** = ce qui est réputé déjà décidé dans l'arbitrage B2.
2. **Source vérifiable** = ce que le dépôt permet effectivement de vérifier.
3. **Exigence héritée** = le minimum qui découle de B2 + de sa source, sans solution d'implémentation imposée.
4. **Traduction D1 candidate** = une manière possible d'opérationnaliser l'exigence dans D1 ; elle reste à arbitrer et ne peut pas être rétro-projetée comme une exigence B2.

### Règle anti-invention

Si une traduction D1 candidate n'est pas strictement nécessaire pour satisfaire l'exigence héritée, elle doit rester **candidate**, même si elle paraît techniquement préférable.

### Règle anti-circularité

Un critère de validation ne peut pas simplement vérifier qu'une règle définie par D1 a été respectée. Il doit pouvoir être évalué à partir d'une propriété indépendante, observable et falsifiable.

### Règle d'indépendance

Aucune définition complète de l'indépendance IA n'est gelée dans D1.2. LAC-18 reste un objet d'arbitrage D1.

# 4. Traitement des findings critiques

## 4.1 LAC-16 — CHAL

Le finding reste **OPEN** et rattaché à D1. D1.2 ne prétend pas avoir déjà choisi l'architecture finale. La matrice ne fait qu'établir le minimum hérité et les éléments qu'une solution D1 devra rendre déterministes.

```text
ÉTAT SOURCE
→ ACTEUR AUTORISÉ
→ PRÉCONDITIONS
→ ACTION
→ AUTORISATION
→ PREUVE
→ ÉTAT CIBLE
→ RECOURS / CHALLENGE
```

## 4.2 LAC-16b — CONTR

Le finding reste **OPEN** et rattaché à D1. La matrice n'impose pas encore un modèle final d'arbitrage.

Minimum à traiter :

```text
CONTRADICTION IDENTIFIÉE
→ QUALIFICATION
→ ANALYSE
→ AUTORITÉ AUTORISÉE
→ DÉCISION
→ JUSTIFICATION
→ VERSION IMPACTÉE
→ ÉTAT TERMINAL
```

## 4.3 LAC-18 — indépendance IA

LAC-18 reste **OPEN — arbitrage requis**. D1.2 ne fige ni seuil numérique, ni architecture IA, ni règle de sélection d'un fournisseur.

Les dimensions à examiner sont seulement candidates :

- provenance des données ;
- données communes ;
- transformations ;
- instructions/prompts ;
- modèle ou pipeline partagé ;
- hypothèses communes ;
- contamination croisée ;
- corrélation méthodologique ;
- capacité d'audit de la chaîne.

## 4.4 LAC-06 — séparation des rôles

LAC-06 reste une dépendance à traiter dans la gouvernance appropriée. D1.2 ne transforme pas une architecture globale de rôles en exigence D1 complète. Seuls les rôles nécessaires à la Research Charter et leurs incompatibilités pertinentes sont tracés ici.
