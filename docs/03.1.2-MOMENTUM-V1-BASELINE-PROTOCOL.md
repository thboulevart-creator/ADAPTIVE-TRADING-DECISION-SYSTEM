# 3.1.2 — MOMENTUM V1 — PREMIER BACKTEST BASELINE PROTOCOL

## Status

**Protocol candidate → adversarially broken → corrected → re-broken → PASS.**

This document defines the first baseline experiment. It does not claim profitability or robustness.

## 1. Objective

Measure the raw behavior of the locked Momentum V1 definition before adding regime filters, optimization, routing, or adaptive logic.

The experiment must answer only:

> What does the frozen Momentum V1 signal do under a fixed, reproducible, realistic test protocol?

It must not answer whether Momentum is optimal.

## 2. Frozen strategy definition

- Timeframe: H1
- Price field: Close
- Horizon: 20 completed H1 bars
- `M_t = Close_t / Close_{t-20} - 1`
- `M_t > 0` → LONG signal
- `M_t < 0` → SHORT signal
- `M_t = 0` → NEUTRE
- insufficient history → UNDEFINED
- signal is computed only after close of bar `t`
- signal becomes actionable only at `t+1`
- no regime filter
- no parameter optimization
- no pyramiding
- no discretionary override
- signal ≠ order

## 3. Dataset gate

The baseline may execute only on a dataset whose identity is explicitly recorded before execution:

- asset;
- source/provider;
- timezone;
- timeframe construction method;
- exact start/end timestamps;
- file/data identity hash;
- data-quality status;
- availability of required tick-level modelling where execution/cost simulation requires it.

The project's mandatory research gate requires **at least five years** before a real backtest is accepted as a qualification result. The currently qualified B05 corpus is a one-month January-2025 corpus and therefore **cannot by itself satisfy the 3.1.2 five-year gate**.

No synthetic extension, copied month, interpolation, or silent fallback is permitted.

## 4. Execution and timing model

For each H1 signal:

1. close bar `t`;
2. calculate Momentum using data through `t` only;
3. record signal;
4. earliest admissible execution is `t+1`;
5. apply the explicitly documented execution/cost model.

No intrabar information from `t` may be used to create an action before `t+1` unless the protocol explicitly proves that the information existed before the decision timestamp.

## 5. Cost model

The baseline must include realistic transaction costs available from the selected execution venue/data source:

- spread;
- commission where applicable;
- slippage where applicable.

The exact numerical assumptions must be recorded with the run artifact. If a required cost is unknown, the run is BLOCKED rather than silently assigning zero.

A later robustness experiment may widen spread, but that is **not** part of the first baseline result and must not be mixed into it.

## 6. Position/exits

3.1.1 defines a directional expert, not a complete trading system. Therefore 3.1.2 must not invent an unrecorded SL/TP or RR rule.

For a baseline to be executable, the experiment must explicitly choose and document one deterministic minimal position/exit convention outside the Momentum signal definition. That convention is an experimental harness, not part of Momentum V1 itself.

Any convention chosen for the harness must be frozen before seeing baseline results and must not be optimized against them.

## 7. Sample split

The experiment must separate:

- development/calibration data, if any;
- untouched out-of-sample data.

For the first baseline, no parameter calibration is permitted. The OOS segment therefore remains a genuine untouched evaluation segment.

The exact split dates must be fixed before execution and persisted with the run.

## 8. Metrics

At minimum record:

- total return / PnL under the chosen fixed risk convention;
- maximum drawdown;
- number of trades/signals acted upon;
- win rate where meaningful;
- average win/loss where meaningful;
- expectancy per trade;
- gross and net costs;
- exposure/time in market;
- performance by long vs short;
- performance by calendar period;
- OOS results separately from any development result.

No single metric is an acceptance criterion for Momentum itself.

## 9. Reproducibility

Every execution must persist:

- exact code/reference commit;
- exact protocol version;
- dataset identity/hash;
- contract identity/hash where applicable;
- execution-cost assumptions;
- date/time window;
- signal/position convention;
- generated result artifact;
- run identifier.

A second execution with identical inputs must produce identical deterministic outputs within the documented numerical representation.

## 10. Anti-overfitting rules

The baseline run is prohibited from:

- sweeping horizons;
- optimizing thresholds;
- selecting the best asset after seeing results;
- changing the exit model after seeing results;
- tuning costs to improve results;
- selecting a favorable OOS period after seeing results;
- adding regime filters;
- adding extra indicators.

Any such experiment becomes a separate candidate and cannot overwrite the baseline.

## 11. Qualification boundary

**PASS of 3.1.2 protocol** means only that the baseline experiment is sufficiently specified, reproducible, adversarially challenged, and executable in principle.

It does not mean Momentum is profitable.

A backtest execution may return PASS/FAIL/BLOCKED independently of the protocol.

## 12. Required evidence chain

`Protocol → adversarial report → corrected protocol → re-break report → verdict → execution artifact → Recovery Checkpoint`
