# 3.1.2 — MOMENTUM V1 — PREMIER BACKTEST BASELINE PROTOCOL

## Status

**PASS — protocole corrigé après cassage et re-cassage.**

This document defines the first baseline experiment. It does not claim profitability or robustness.

## 1. Objective

Measure the raw behavior of the locked Momentum V1 definition before regime filters, optimization, routing, or adaptive logic.

Question answered only:

> What does the frozen Momentum V1 signal do under a fixed, reproducible, realistic test protocol?

It must not answer whether Momentum is optimal.

## 2. Frozen strategy definition

- Timeframe: H1
- Price field: Close
- Horizon: 20 completed H1 bars
- `M_t = Close_t / Close_{t-20} - 1`
- `M_t > 0` → LONG signal
- `M_t < 0` → SHORT signal
- `M_t = 0` → NEUTRE
- insufficient history → UNDEFINED
- signal calculated only after close of `t`
- signal usable only from `t+1`
- no regime filter
- no parameter optimization
- no pyramiding
- no discretionary override
- signal ≠ order

## 3. Dataset gate

Before execution, record:

- asset;
- source/provider;
- timezone;
- timeframe construction method;
- exact start/end timestamps;
- dataset/file identity hash;
- data-quality status;
- availability of required tick-level data for execution/cost simulation.

The project's mandatory research gate requires **at least five years** before a real backtest is accepted as a qualification result. The B05 January-2025 corpus is one month and therefore **cannot satisfy this gate by itself**.

No synthetic extension, copied month, interpolation, silent fallback, or substitution is allowed.

## 4. Frozen position/execution harness

To prevent the baseline from inventing an exit rule after seeing results, the following minimal harness is frozen before execution:

1. A LONG signal at close `t` creates a +1 normalized position at the first admissible execution point of `t+1`.
2. A SHORT signal creates a -1 normalized position at the first admissible execution point of `t+1`.
3. A NEUTRE signal creates/maintains flat state.
4. An opposite directional signal closes the current position and reverses to the new direction at the first admissible execution point of that next bar.
5. No stop-loss, take-profit, trailing stop, break-even, pyramiding, scaling, or discretionary exit is used in this baseline.
6. Position size is fixed at normalized unit exposure; this is a research measurement convention, not a risk recommendation.
7. Entry/exit price is the first admissible price of `t+1` supplied by the execution data. If the execution source cannot identify that price deterministically, execution is BLOCKED.

This harness is deliberately simple. It belongs to the baseline experiment, not to the definition of Momentum V1.

## 5. Timing / look-ahead control

For every signal:

1. finish bar `t`;
2. calculate Momentum from data through `t` only;
3. freeze the signal;
4. earliest action is on `t+1`;
5. apply the fixed execution/cost model.

No intrabar information from `t` may influence the decision.

## 6. Cost model

The baseline must include the documented realistic costs available for the selected execution source:

- spread;
- commission where applicable;
- slippage where applicable.

Exact numerical assumptions are recorded with the run. If a required cost is unknown, the run is **BLOCKED**, not assigned zero.

Spread widening is a separate robustness experiment and is not mixed into the baseline.

## 7. Sample split

The execution window must be fixed before results are observed.

- Development/calibration: none for the baseline.
- OOS: the untouched evaluation segment fixed before execution.
- The exact split dates are persisted with the run.

No result may be used to move the split.

## 8. Metrics

Record at minimum:

- normalized gross and net PnL/return;
- maximum drawdown;
- number of acted-on directional signals/trades;
- win rate where meaningful;
- average win/loss where meaningful;
- expectancy per trade;
- gross costs and net costs;
- exposure/time in market;
- long vs short results;
- results by calendar period;
- OOS results separately.

No single metric is an acceptance criterion for Momentum itself.

## 9. Reproducibility

Persist:

- exact code/reference commit;
- exact protocol version;
- dataset identity/hash;
- contract identity/hash where applicable;
- execution/cost assumptions;
- exact time window and OOS split;
- fixed signal/position convention;
- generated result artifact;
- run identifier.

Identical inputs must produce identical deterministic outputs within the documented numerical representation.

## 10. Anti-overfitting rules

The baseline may not:

- sweep horizons;
- optimize thresholds;
- select an asset after seeing results;
- change the position/exit harness after seeing results;
- tune costs to improve results;
- move the OOS split after seeing results;
- add regime filters;
- add extra indicators.

Any such change is a separate experiment.

## 11. Qualification boundary

**3.1.2 protocol PASS** certifies only that the baseline experiment is sufficiently specified, reproducible, adversarially challenged, and executable in principle.

It does not certify profitability, robustness, economic value, or superiority.

The actual backtest execution has its own PASS/FAIL/BLOCKED verdict.

## 12. Evidence chain

`Protocol → adversarial break → correction → re-break → protocol verdict → execution artifact → Recovery Checkpoint`
