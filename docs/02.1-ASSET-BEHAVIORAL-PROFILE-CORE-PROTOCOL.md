# ASSET BEHAVIORAL PROFILE CORE — PROTOCOL V0.1

Statut : CANDIDATE FOUNDATION  
Date : 2026-09-25

## 1. Objet

Construire une mémoire empirique, strategy-agnostic et auditable du comportement de l'actif avant toute recherche d'edge.

Entrée autorisée initiale :

`SOURCE_B_USTECH_PRICE_CORE_V0_1`

Champs autorisés :
- timestamp ;
- bid_price ;
- ask_price.

Volumes interdits tant que non qualifiés.

## 2. Principe

Le système doit d'abord répondre :

```text
COMMENT CET ACTIF SE COMPORTE-T-IL ?
```

avant de demander :

```text
COMMENT LE TRADER ?
```

Une observation comportementale n'est jamais une stratégie.

Exemple :

`compression < p20 suivie d'une expansion`

est une observation candidate.

`acheter la compression`

est une hypothèse de stratégie et appartient à une phase ultérieure.

## 3. Séparation épistémique

Chaque résultat doit être typé :

- OBSERVATION ;
- DESCRIPTION ;
- HYPOTHESIS ;
- TEST ;
- RESULT ;
- VALIDATED_KNOWLEDGE ;
- REJECTED_HYPOTHESIS.

Le CORE produit principalement OBSERVATION/DESCRIPTION.

Il ne produit pas :
- signal ;
- position ;
- trade ;
- PnL ;
- optimisation ;
- sélection d'expert.

## 4. Transformation canonique AP0

Avant les statistiques comportementales, créer une DatasetIdentity dérivée :

`USTECH_PROFILE_MINUTE_CORE_V0_1`.

Granularité :
**1 minute UTC**, sans forward-fill.

Source :
SOURCE_B_USTECH_PRICE_CORE_V0_1.

Pour chaque minute contenant au moins un tick :

- minute_start_utc ;
- first_tick_ms ;
- last_tick_ms ;
- tick_count ;
- mid_open ;
- mid_high ;
- mid_low ;
- mid_close ;
- spread_mean ;
- spread_min ;
- spread_max.

Définition :
`mid = (bid_price + ask_price) / 2`.

Aucune minute synthétique n'est créée.

## 5. Gap awareness

La transformation ne doit jamais masquer les interruptions.

Elle doit conserver ou dériver :
- temps depuis le dernier tick précédent ;
- rupture >60 s ;
- frontière de session régulière si applicable ;
- interruption suspecte/open-session ;
- segment_id.

Un nouveau `segment_id` commence après toute interruption >60 s.

Conséquence :
- aucun retour continu ne traverse un changement de segment ;
- les mouvements de réouverture peuvent être étudiés séparément comme gap/reopen behavior.

## 6. Time semantics

Horloge brute autorisée :
UTC/GMT pour la session régulière, sous la clôture DATA TRUTH.

Dimensions temporelles dérivables ultérieurement :
- UTC hour/minute ;
- America/New_York local time ;
- weekday ;
- session ;
- DST regime.

Aucune conversion Europe/Paris n'est autorisée comme sémantique source.

## 7. Modules CORE

### AP1 — Intraday behavior

Mesurer sans stratégie :
- tick activity par minute/heure ;
- range par minute/heure ;
- volatilité par heure ;
- spread par heure ;
- comportement autour de l'ouverture/réouverture ;
- stabilité par année.

### AP2 — Volatility map

Mesurer :
- realized range ;
- absolute/log return sur segments continus ;
- distributions et percentiles ;
- volatilité par horizon ;
- clusters de volatilité ;
- extrêmes.

### AP3 — Expansion / compression

Définir des mesures strategy-agnostic :
- compression relative aux distributions historiques ;
- expansion relative ;
- durée des phases ;
- transition compression→expansion ;
- transition expansion→normalisation.

Les seuils initiaux doivent être descriptifs/quantiles, pas optimisés sur un résultat de trading.

### AP4 — Price structure

Mesurer :
- persistance directionnelle ;
- amplitude des swings ;
- durée des mouvements ;
- fréquence des retournements ;
- breakouts descriptifs ;
- réintégrations ;
- gap/reopen behavior.

Aucune règle d'entrée/sortie.

### AP5 — Microstructure price-core

Mesurer :
- spread moyen/médian/percentiles ;
- spread par heure/session ;
- spread extrême ;
- relation spread ↔ volatilité ;
- tick density.

Volume et profondeur restent hors scope V0.1.

### AP6 — Seasonality / stability

Comparer :
- heure ;
- jour de semaine ;
- mois ;
- année ;
- sous-périodes ;
- stabilité des distributions.

Tout pattern doit être accompagné d'une mesure de stabilité temporelle.

## 8. Interdictions

Pendant le CORE :
- aucune stratégie rentable/non rentable ;
- aucun Sharpe/Profit Factor/PnL ;
- aucun parameter sweep orienté performance ;
- aucune sélection d'indicateur par résultat ;
- aucun expert routing ;
- aucun régime choisi pour améliorer une stratégie ;
- aucun MT5.

## 9. Mémoire

Chaque découverte doit mémoriser :
- dataset identity ;
- transformation identity ;
- métrique ;
- période ;
- méthode ;
- résultat ;
- stabilité ;
- limites ;
- hypothèses générées ;
- contradictions.

- métriques documentées ;
- aucun calcul de stratégie ;
- stabilité temporelle mesurée ;
- limites et données non qualifiées explicites.
