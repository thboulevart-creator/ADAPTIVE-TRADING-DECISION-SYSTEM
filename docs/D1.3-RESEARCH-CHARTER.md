## 0. Objet de la Charter

Cette Charter définit le cadre d'une **recherche confirmatoire D1** avant tout calcul confirmatoire.

Elle ne définit pas encore une stratégie de trading, un modèle d'exécution, une architecture D2–D7 ou un contrat de données. Elle définit uniquement les conditions permettant qu'une recherche donnée soit reconnue comme **confirmatoire, traçable, falsifiable et reproductible**.

### Question de cadrage

> **Quelle hypothèse précise, économiquement ou comportementalement justifiée, peut être soumise à un test confirmatoire dont les frontières, le budget de recherche, l'échantillon, le protocole et les critères de décision sont définis avant le premier calcul confirmatoire ?**

# 2. Hypothèse confirmatoire

## 2.1 Hypothèse

**À compléter avant lancement :**

> HYPOTHÈSE : `[énoncé falsifiable précis]`

## 2.2 Justification économique / comportementale

La Charter doit expliciter :

1. **Acteur(s) ou contrainte(s)** supposés pertinents ;
2. **Mécanisme causal / comportemental** proposé ;
3. **Trace observable** attendue dans les données ;
4. **Limites et conditions** dans lesquelles le mécanisme ne devrait pas s'appliquer.

Aucune justification ne peut être constituée uniquement par l'apparence graphique ou la performance historique.

## 2.3 Prédiction testable

> PRÉDICTION : `[observation qui devrait être constatée si H1 est vraie]`

## 2.4 Conditions de falsification

> FALSIFICATION : `[observation définie ex ante qui conduirait à rejeter l'hypothèse]`

Une absence d'interprétabilité doit rester distincte d'une falsification.

**Source D1.2 :** B2-D1-05, B2-D1-06, B2-D1-16.

---

# 3. Frontières gelées

Avant tout calcul confirmatoire, la Charter doit fixer au minimum :

- actif(s) concerné(s) ;
- période(s) et frontières temporelles ;
- horizon(s) d'observation ;
- unité d'observation ;
- conventions nécessaires au test ;
- règles d'inclusion ;
- règles d'exclusion ;
- séparation conception / confirmation / hors échantillon lorsque pertinente ;
- artefacts techniques influençant le résultat.

Les frontières ne doivent pas être modifiées silencieusement après observation d'un résultat.

**Source D1.2 :** B2-D1-07 et B2-D1-08.

> **Important :** cette section ne reprend aucune règle supplémentaire de `05-DATA-CONTRACT.md`. Les détails du contrat de données restent hors de cette Charter tant qu'ils ne sont pas hérités explicitement par D1.

# 5. Échantillon et unité statistique

## 5.1 Taille d'échantillon ex ante

Avant le premier calcul confirmatoire, la Charter doit préciser :

- unité statistique ;
- effet minimal détectable, lorsque pertinent ;
- puissance visée, lorsque pertinente ;
- méthode de détermination de N ;
- disponibilité réelle de l'échantillon ;
- traitement des dépendances pertinentes.

Le résultat observé ne peut pas servir à déterminer rétroactivement la taille nécessaire.

## 5.2 Dépendance / autocorrélation / agrégation

La Charter doit expliciter pourquoi l'unité choisie constitue une unité statistique pertinente et comment les dépendances éventuelles sont traitées.

**Source D1.2 :** B2-D1-11 et B2-D1-12.

---

# 6. Spécification statistique ex ante

Avant le calcul confirmatoire, la Charter doit identifier au minimum :

- H0 ;
- H1 ;
- test ou procédure statistique ;
- direction statistique lorsqu'un test unilatéral est utilisé ;
- seuil / règle de décision applicable ;
- métrique primaire ;
- métriques secondaires, si nécessaires ;
- traitement des données manquantes / exclusions pertinentes ;
- procédure empêchant les choix post hoc sur les éléments critiques.

**Source D1.2 :** B2-D1-13 et B2-D1-14.

> **Principe :** aucune métrique particulière n'est imposée ici si elle n'est pas héritée de D1.2. Le choix concret reste une décision de Charter à documenter et à justifier.

---

# 7. Contrôles et critères de promotion

Toute condition critique de promotion doit être définie sous la forme :

`condition → périmètre → procédure → critère de rejet → rôle → preuve`

La Charter doit permettre d'identifier :

- ce qui est contrôlé ;
- qui peut exécuter le contrôle ;
- qui ne peut pas être seul juge de son propre contrôle lorsque cette incompatibilité est retenue ;
- quel résultat constitue un échec ;
- quelle preuve est conservée.

**Source D1.2 :** B2-D1-15.

La matrice des rôles détaillée et les incompatibilités restent **à arbitrer** ; D1.3 ne doit pas inventer leur résolution à partir du finding LAC-06/LAC-10.

---

# 8. Décision scientifique

Deux issues doivent rester distinctes :

### A — HYPOTHÈSE RÉFUTÉE

La prédiction falsifiable n'est pas soutenue selon la règle définie ex ante.

### B — ESSAI NON INTERPRÉTABLE

Le protocole, les données, la reproduction ou un contrôle critique ne permettent pas d'interpréter le résultat selon la Charter.

Un essai non interprétable ne doit pas être transformé artificiellement en résultat positif ou négatif.

**Source D1.2 :** B2-D1-16.

---

# 9. Reproductibilité indépendante

Cette section est **CANDIDATE — À ARBITRER**.

D1.2 établit le besoin de reproductibilité indépendante mais laisse explicitement ouverte la définition de l'indépendance.

La Charter doit donc, avant gel, arbitrer au minimum :

- indépendance de provenance ;
- indépendance d'accès aux données / artefacts ;
- indépendance des transformations ;
- indépendance des instructions ;
- indépendance des modèles / outils lorsque pertinent ;
- indépendance des hypothèses et décisions analytiques ;
- risque de contamination entre analystes ;
- corrélation méthodologique acceptable ou non ;
- gestion des divergences entre reproductions.

**Aucun seuil numérique n'est fixé dans cette version 0.1.**

**Source D1.2 :** B2-D1-17 et finding LAC-10.

# 11. Traçabilité des données utilisées

D1.2 conserve comme exigence héritée la traçabilité des données réellement utilisées, sans importer implicitement `05`.

La Charter doit donc pouvoir référencer :

- source utilisée ;
- version / identifiant disponible ;
- périmètre effectivement utilisé ;
- lien avec le calcul confirmatoire ;
- preuve permettant de reconstruire ce qui a effectivement été utilisé.

**Interdit dans D1.3 :** transformer cette exigence de traçabilité en adoption silencieuse de règles détaillées de `05-DATA-CONTRACT.md`.

**Source D1.2 :** B2-D1-22.

---

# 12. Gel de la Charter

Une Charter D1 applicable doit disposer avant le premier calcul confirmatoire de :

- identifiant unique ;
- version ;
- date / heure de gel ;
- hash ou mécanisme d'identification équivalent ;
- acteur autorisé à geler ;
- justification ;
- historique de versions précédentes lorsqu'il existe ;
- référence aux hypothèses, frontières, budget, échantillon, protocole et contrôles gelés.

Toute modification substantielle après gel doit être identifiable et ne peut pas remplacer silencieusement la version antérieure.

**Source D1.2 :** B2-D1-02, B2-D1-04.

# 14. Conditions de gel D1.3

D1.3 ne pourra être gelée que lorsque :

1. chaque élément obligatoire est renseigné ;
2. chaque décision candidate est explicitement arbitrée ;
3. aucune proposition candidate n'est présentée comme héritage B2 sans source ;
4. les frontières sont gelées ;
5. le budget de recherche est déterminé ;
6. l'échantillon et l'unité statistique sont déterminés ;
7. le protocole statistique est pré-spécifié ;
8. les contrôles critiques disposent d'un critère falsifiable ou de rejet ;
9. les rôles et incompatibilités nécessaires sont arbitrés ;
10. l'indépendance de reproduction est définie de façon testable ;
11. les données réellement utilisées restent traçables sans adoption implicite de `05` ;
12. un re-audit adversarial / contre-expertise de la Charter ne révèle aucun défaut bloquant.
